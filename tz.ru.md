# ТЗ: PocketPCB — мини-редактор схем и печатных плат

Черновик, начат 2026-11-12, обновлён 2026-11-13. Будет дополняться.

## Цель и рамки

Маленький и простой редактор принципиальных схем и двухсторонних печатных плат для ручной разводки. Не конкурент KiCad: минимум функций, максимум простоты.

- Несколько встроенных УГО и посадочных мест (не большая библиотека).
- Двухсторонние платы, разводка вручную, без автотрассировки.
- Обязательный результат: файлы Gerber + сверловка для заказа платы на производстве, а также печать слоёв 1:1 для изготовления дома (ЛУТ, фоторезист).
- Всё, что отложено на следующие версии, собрано в разделе «Отложено на потом». Для таких вещей модель данных и формат файла по возможности готовятся сразу, чтобы потом не переделывать.

## Решения

- Схема и плата — одна программа, общая модель данных (2026-11-12).
- **Файлы проекта** (2026-11-13), все — JSON, в одной папке проекта:
    - `имя.ppcb` — проект: свойства и поля штампа, классы цепей, правила разводки, настройки сетки; ссылки на файлы схемы и платы;
    - `имя.ppsch` — схема (все листы);
    - `имя.ppbrd` — плата.
  Открывается файл `.ppcb`; схема и плата загружаются вместе с ним. Команда «Сохранить» сохраняет все изменённые файлы сразу. Автосохранение и резервные копии `.bak` — для каждого файла.
- Библиотека деталей — файлы `.json`, разложенные по папкам `symbols/`, `footprints/`, `parts/`; пишутся вручную (2026-11-12). Две библиотеки: встроенная (поставляется с программой, только чтение — внутри AppImage) и пользовательская (в папке данных пользователя, через `QStandardPaths`). Загружаются обе; пользовательская может переопределять встроенные детали.
- Один проект = одна схема (возможно, на нескольких листах) + одна плата. Отдельный модуль (например, плата, вставляемая в основную) — отдельный проект. Библиотека деталей общая для всех проектов (2026-11-13).
- Язык C++ (рассматривался Free Pascal/Lazarus — автору он ближе, но выбран C++/Qt6 ради готового холста `QGraphicsScene`) (2026-11-12).
- Стиль кода: простой и читаемый. Без шаблонной магии, сложного метапрограммирования и экзотических возможностей C++. Понятные имена, небольшие классы и функции — код должен быть понятен человеку с опытом Pascal.
- Язык: весь код и комментарии — на английском. ТЗ пишется на русском, потом переводится на английский. Общение с автором — на русском (2026-11-12).
- Интерфейс многоязычный: английский, украинский, русский; язык переключается в настройках, по умолчанию — язык системы (если он из этих трёх, иначе английский). Реализация штатными средствами Qt (`tr()`, Qt Linguist, файлы .ts/.qm). Все строки интерфейса в коде — на английском, через `tr()` (2026-11-12).
- Детали первой версии: только выводные (THT), список — в разделе «Библиотека деталей». Модель данных сразу допускает SMD: площадка может быть без отверстия и только на одном слое, деталь может стоять на нижней стороне (с зеркалированием) (2026-11-12).
- Название — **PocketPCB**; исполняемый файл и имя репозитория — `pocketpcb` (2026-11-13).
- Проект открытый, лицензия GPL-3.0-or-later; код публикуется на GitHub (когда — решает автор; до этого — локальный репозиторий git). Совместимость зависимостей: Qt6 (LGPLv3) — да, Clipper2 (Boost) — да, штриховой шрифт Newstroke из KiCad (GPL-2.0-or-later, нарисован по шрифтам Hershey) — да (2026-11-13, шрифт сменён 2026-11-19).
- Формат всех файлов — JSON, средствами Qt (`QJsonDocument`), в едином стиле (2026-11-12).
- Связи с первой версии: схема → нетлист → линии связей (ratsnest) на плате. Модель данных строится вокруг цепей (nets) с самого начала (2026-11-12).

## Платформа и стек

C++ и Qt6, сборка через CMake. Разработка — на Linux. Целевые ОС: Linux сейчас, Windows 10+ — позже. Код с самого начала переносимый, без платформенно-специфичных вызовов (пути — через `QDir`/`QStandardPaths`, без жёстко заданных разделителей), чтобы Windows-сборка потом не требовала переделок.

- **Сборка и распространение (2026-11-13):** пока всё собирается локально на машине автора (Linux Mint 22.3, база Ubuntu 24.04 noble), без GitHub Actions. Результат — AppImage. Qt не собирается статически: библиотеки Qt и плагины кладутся внутрь AppImage (linuxdeploy + linuxdeploy-plugin-qt). AppImage запускается на системах с базой Ubuntu 24.04 и новее; более старые (например, Mint 21) в первой версии не поддерживаются.
- В репозитории — скрипт сборки AppImage (одна команда: сборка, тесты, упаковка), чтобы процесс был повторяемым и его легко было потом перенести в GitHub Actions.
- **Версия Qt:** та, что есть в репозиториях Ubuntu 24.04 (пакет `qt6-base-dev`; по памяти — Qt 6.4, точную версию проверить командой `apt policy qt6-base-dev`). Код не использует возможности новее этой версии.

- Холст редактора на `QGraphicsScene` / `QGraphicsView`: зум, панорамирование, выделение, слои.
- Undo/Redo через `QUndoStack` закладывается с первого дня.
- Геометрия: свои простые функции расстояний (отрезок, окружность, прямоугольник). Clipper2 подключается вместе с заливкой медью.

## Единицы и сетка

Внутри программы все координаты и размеры хранятся целыми числами в нанометрах (`int64`), без `double`. Причины: нет накопления ошибок округления, точное сравнение координат, и в нанометрах целыми получаются и метрические, и дюймовые значения (1 мил = 25 400 нм). Во всех JSON-файлах (проект, схема, плата, библиотека) размеры пишутся в мм десятичными числами (например `2.54`), чтобы их было удобно читать и писать руками; при загрузке они переводятся в нанометры с округлением.

- Сетка дюймовая, под шаг выводов DIP и штыревых разъёмов. Набор шагов: 0.635, 1.27, **2.54 (по умолчанию)**, 5.08, 10.16 мм. Переключение шага — горячими клавишами и из выпадающего списка (набор крупных шагов предварительный).
- Все размеры в интерфейсе — в мм.

## Библиотека деталей

Три вида объектов, каждый в своём JSON-файле:

1. **УГО (символ):** графика (линии, прямоугольники, окружности, дуги, текст) и выводы. У вывода: номер, имя, координаты, направление (с какой стороны подходит провод). Выводы стоят в узлах сетки 2.54 мм.
2. **Посадочное место:** площадки (номер, форма, размер, отверстие, слои) и контур корпуса для шелкографии.
3. **Деталь:** связывает УГО с одним или несколькими допустимыми посадочными местами, задаёт префикс обозначения (R, C, VT, DD …), номинал по умолчанию и название для панели библиотеки на всех языках интерфейса (`"name": {"en": …, "uk": …, "ru": …}`; если перевода нет — английское, если нет и его — имя файла) (2026-11-14). Признак «соединитель» — у разъёмов и площадок под провод (используется в ERC). Связь выводов с площадками — по номерам (вывод 1 → площадка 1).

Микросхема в первой версии — один символ со всеми выводами (2026-11-13).

УГО и посадочное место разделены, потому что одна деталь бывает в разных корпусах (резистор с шагом 7.62 или 10.16 мм). Конкретное посадочное место выбирается при расстановке детали на схеме и меняется в её свойствах.

**Детали копируются в проект** (2026-11-13): при расстановке деталь, её УГО и посадочное место копируются в папку `library/` рядом с файлом проекта (в той же раскладке `symbols/`, `footprints/`, `parts/`), по одной копии на деталь, сколько бы раз она ни стояла на схеме. Компонент в файле схемы хранит только ссылку на деталь и выбранное посадочное место, обозначение, номинал и положение (2026-11-16). Проект не зависит от библиотеки: открывается таким, каким был сохранён, даже если деталь в библиотеке изменили или удалили. Команда «Обновить детали из библиотеки» показывает различия и обновляет выбранные детали (одним шагом Undo).

**Префиксы обозначений:** у каждой детали в библиотеке два префикса — международный (R, C, D, LED, Q, U, J, SW, BT, LS …) и по ГОСТ (R, C, VD, HL, VT, DD, X, SA, GB, BA …). Переключатель стиля в настройках проекта, по умолчанию международный. При переключении обозначения в проекте переименовываются (номера сохраняются; одним шагом Undo).

**Состав библиотеки первой версии** (только выводные детали):

- пассивные: резистор, переменный резистор (потенциометр), подстроечный резистор, конденсатор, электролитический конденсатор, катушка индуктивности, кварцевый резонатор (HC-49), предохранитель;
- полупроводники: диод, светодиод, транзисторы (TO-92, TO-220), тиристор (TO-220), микросхемы DIP-8 / DIP-14 / DIP-16;
- коммутация: тумблер, кнопка, галетный переключатель (несколько вариантов положений/направлений);
- звук и питание: элемент питания / батарея, динамик, зуммер (buzzer);
- соединители: штыревой разъём 1×N, винтовые клеммники (2, 3 контакта), гнездо питания (DC jack), аудиогнездо (jack 3.5 / 6.3), площадка под провод.

**Корпусные детали** (2026-11-13) — гнездо питания, аудиогнездо, галетный переключатель, тумблер, потенциометр, динамик, батарея — в библиотеке только УГО, без посадочного места, с признаком «не на плате» по умолчанию. На плату они подключаются проводами через площадки под провод. Посадочные места для них не рисуются, поэтому сверять размеры с документацией не нужно.

Признак «не на плате» можно включить у **любой** детали в схеме — например, мощный транзистор, диод или тиристор на радиаторе, мощный резистор или крупный конденсатор, закреплённые на корпусе. Выключить его можно только у детали, у которой есть посадочное место. Детали с посадочными местами: резисторы, подстроечный резистор, конденсаторы, катушка, кварц, предохранитель, диод, светодиод, транзистор (TO-92, TO-220), тиристор (TO-220), микросхемы DIP, кнопка, зуммер, штыревой разъём, винтовые клеммники (шаг 5.0 / 5.08 мм), площадка под провод.

## Редактор схемы

Схема рисуется на той же дюймовой сетке; выводы УГО всегда стоят в узлах сетки 2.54 мм.

- **Листы:** схема может состоять из нескольких листов (плоская структура, без иерархии). Листы переключаются вкладками; их можно добавлять, удалять, переименовывать и менять порядок. У каждого листа свой формат (A4/A3) и своё название в штампе. Позиционные обозначения сквозные на весь проект (R1…Rn без повторов между листами).
- **Стиль УГО:** ГОСТ / IEC 60617 (резистор — прямоугольник, катушка по ГОСТ, логика — прямоугольники с символом функции `&`, `1`, `=1`). Американских (ANSI) обозначений нет. Строгого соответствия ГОСТ по размерам не требуется — важен вид обозначений.
- **Провода:** горизонтально, вертикально и под 45°. Провод — ломаная из отрезков.
- **Соединения:** провод соединяется с выводом или другим проводом, только если конец попадает точно в точку. В Т-образном соединении автоматически ставится точка.
- **Метки цепей:** провода с одинаковой меткой соединены, даже если между ними нет провода, — на всех листах проекта. У метки в модели сразу есть признак области действия «глобальная» / «локальная»; в первой версии работают только глобальные.
- **Символы питания и земли** (GND, +5V, +3.3V …): особый вид метки цепи — все символы с одинаковым именем соединены по всему проекту.
- **Обозначения и номиналы:** у каждой детали есть позиционное обозначение (R1, C3, DD2) и номинал (10k, 100n, NE555). Новая деталь получает следующий свободный номер своего типа. Есть команда перенумерации по порядку (слева направо, сверху вниз). Обозначение и номинал видны на схеме и на шелкографии платы, их можно перемещать мышью.
- **Цепи без метки** получают автоматическое имя (например `N1`, `N2` …); имя видно в списке цепей и при наведении.
- **Шины:** шина — графический объект с именем вида `D[0..7]`. Сама по себе ничего не соединяет; провод подключается к шине через ответвление с меткой (`D0`, `D1` …), и соединение образуют одинаковые метки. Так нетлист строится по одному правилу — по меткам.

- **Свободная графика:** текст (комментарии) и линии, прямоугольники (сплошные и пунктирные — например, рамки вокруг функциональных блоков). На соединения не влияют.
- **Детали «не на плате»:** у детали есть флаг «не на плате» (переменный резистор на корпусе, выключатель, гнездо на панели и т. п.). Такая деталь есть на схеме и в BOM, но не переносится на плату, и посадочное место ей не нужно. Подключение к плате — через разъём или площадки под провод (деталь-контакт) на схеме (2026-11-13):
    - контакты можно ставить вручную на провод, идущий к детали;
    - команда **«Расставить контакты»** сама ставит контакт у каждого вывода детали «не на плате», если его цепь идёт на плату (содержит детали на плате) и контакта там ещё нет. Выводы, соединённые только с другими деталями «не на плате» (например, батарея → тумблер), пропускаются. Дальше контакты можно двигать, удалять и добавлять вручную; команда — один шаг Undo;
    - на плате у площадки под провод на экране всегда видна подпись, к чему она идёт (например, `R5.2`, `XS1.1`); на шелкографию подпись выводится по желанию.

## Проверка схемы (ERC)

Запускается командой; результат — список, щелчок по строке переводит к месту на схеме.

- Предупреждения: вывод детали ни к чему не подключён; цепь с одним выводом; провод висит одним концом; одинаковые позиционные обозначения; вывод детали «не на плате» подключён к цепи, в которой нет ни одного соединителя (разъёма или площадки под провод).
- Ошибка: деталь без посадочного места (кроме деталей «не на плате»).
- Маркер «не подключать» (крестик) на выводе отключает предупреждение о неподключённом выводе.
- Проверки типов выводов (вход/выход/питание) нет.

## Окно программы

- В центре — холст; над ним вкладки: листы схемы и плата.
- Слева — панель инструментов текущего режима (провод, метка, дорожка, переходное …).
- Справа — сворачиваемые панели: свойства выделенного; библиотека деталей (поиск и предпросмотр); слои (на плате); список цепей (с классами цепей).
- Внизу — строка состояния: координаты курсора (мм), шаг сетки, текущий слой и ширина дорожки.
- Расположение и размеры панелей запоминаются между запусками (`QDockWidget`, `QSettings`).

## Управление (общее для схемы и платы)

- **Панорамирование:** перемещение мыши с зажатой правой кнопкой. Короткий щелчок правой кнопкой без движения открывает контекстное меню. Средняя кнопка тоже панорамирует.
- **Масштаб:** колесо мыши. При каждом шаге колеса точка под курсором переносится в центр экрана, масштаб меняется относительно неё, и курсор мыши тоже переводится в центр экрана, чтобы остаться на той же точке рисунка (как опция «Center and warp cursor on zoom» в KiCad). В настройках есть переключатель на обычный режим, когда точка под курсором остаётся на месте и ничего не центрируется.
- **Горячие клавиши:** за основу берётся раскладка KiCad (как распространённый стандарт); точный список сверяется с документацией KiCad при реализации. Все клавиши переназначаются в настройках (через `QAction`).

## Редактирование (общее для схемы и платы)

- **Выделение:** щелчок — один объект; Shift + щелчок — добавить/убрать из выделения; рамка мышью — всё, что попало в рамку; Ctrl+A — всё на листе/плате. Выделено может быть сколько угодно объектов.
- **Операции над выделением (одним объектом или группой):** перемещение, поворот на 90° (группа — вокруг своего центра), зеркалирование, копирование и вставка (в том числе между листами схемы), удаление. Все операции отменяются через Undo.
- **Перетаскивание с соединениями (обязательно):** при перемещении детали подключённые провода (на схеме) и дорожки (на плате) не отрываются, а тянутся за ней. Это режим по умолчанию. Отдельной клавишей — перемещение без соединений (провода/дорожки остаются на месте и отсоединяются).
    - На схеме провод перестраивается так, чтобы сохранить горизонтальные/вертикальные/45° отрезки (при необходимости добавляется излом).
    - На плате: растягивается последний отрезок дорожки у площадки (может получиться любой угол); нарушение зазора покажет DRC. Умного перестроения дорожек нет.

## Синхронизация схемы и платы

Только в одну сторону: схема → плата.

- Команда «Обновить плату из схемы» запускается вручную; перед применением показывается список изменений. Всё обновление — один шаг Undo.
- Новые детали появляются на плате сбоку от контура.
- Удалённые со схемы детали удаляются с платы вместе с подключёнными дорожками (с подтверждением).
- Изменения связей обновляют ratsnest; дорожки, соединяющие уже не то, подсвечиваются ошибкой, но не удаляются.

## Редактор платы

Два медных слоя (верх и низ), разводка вручную по сетке.

- **Слои:** медь верх/низ, маска верх/низ, шелкография верх/низ, контур платы.
- **Дорожка:** отрезки с шириной и круглыми концами. Формат файла сразу допускает дуги в дорожках.
- **Прокладка дорожек:** углы — горизонталь, вертикаль, 45°; с зажатой клавишей — любой угол. Во время прокладки клавиша переходного ставит переходное отверстие и переводит дорожку на другой слой. Дорожка прилипает к центру площадки, когда курсор рядом. Во время прокладки подсвечиваются все площадки этой цепи.
- **Площадки:** круг, прямоугольник, овал; с отверстием (или без — для будущих SMD).
- **Переходное отверстие:** круг с отверстием.
- **Контур платы:** замкнутый многоугольник из отрезков горизонтально, вертикально и под 45° — так получаются прямоугольные вырезы по краю и скосы. Рисуется тем же инструментом, что и дорожки, на сетке. Для быстрого старта есть команда «прямоугольная плата» (ширина, высота). Любой угол контура можно скруглить (радиус задаётся для угла, 0 — без скругления).
- **Монтажные отверстия:** круглые, любого диаметра, ставятся в любом месте платы, сколько угодно. Флаг «металлизированное» (по умолчанию выключен); если включён — вокруг отверстия медное кольцо (ширина задаётся), которое можно подключить к цепи (например, GND).
- **Шелкография:**
    - контуры корпусов берутся из посадочных мест библиотеки;
    - позиционные обозначения показываются по умолчанию; номиналы скрыты, включаются для отдельной детали или для всех сразу;
    - можно добавить свой текст (название платы, версия, дата) и простые линии;
    - на нижней стороне — зеркально (для деталей и текста снизу);
    - текст — латиница и кириллица;
    - шрифт — встроенный штриховой (буквы из линий заданной толщины), одинаковый на экране, в печати и в Gerber, на любом компьютере. Выбран шрифт Newstroke из KiCad (2026-11-19, вместо Hershey): он нарисован по Hershey и содержит в одном стиле латиницу, кириллицу с украинскими буквами, греческие буквы и знаки ± ° µ Ω.

## Правила разводки и DRC

- **DRC** проверяет зазоры между дорожками, площадками, переходными и краем платы, ширину дорожек и пояски площадок.
- **Уровень каждой проверки** настраивается: ошибка / предупреждение / выключено. Касание или пересечение меди разных цепей (короткое замыкание) — всегда ошибка, отключить нельзя. По умолчанию: нарушение зазора — ошибка; поясок площадки, дорожка уже своего класса, зазор до края платы — предупреждения. Решение по «мелким» проблемам остаётся за автором.
- **Маска:** окно в маске больше площадки на 0.1 мм с каждой стороны (значение в правилах). Переходные отверстия по умолчанию закрыты маской; переключатель в правилах проекта — «закрыты / открыты».
- **Правила** хранятся в проекте, меняются в диалоге настроек.
- **Наборы правил:** переключатель «Производство» / «ЛУТ». После переключения отдельные значения можно поправить вручную. Существующие дорожки и переходные при переключении не меняются — DRC просто проверяет их по новым правилам.

| Параметр | Производство (по умолчанию) | ЛУТ |
| --- | --- | --- |
| Ширины дорожек на выбор, мм | 0.3, 0.5, 0.8, 1.0, 1.5 | 0.5, 0.8, 1.0, 1.5, 2.0 |
| Ширина по умолчанию, мм | 0.5 | 0.8 |
| Зазор медь–медь, мм | 0.3 | 0.5 |
| Переходное: сверло / площадка, мм | 0.6 / 1.2 | 0.8 / 2.0 (под пропайку проволокой) |
| Минимальный поясок площадок, мм | 0.3 | 0.6 |
| Зазор до края платы, мм | 0.5 | 1.0 |

Значения набора «Производство» взяты с запасом, не под конкретного производителя.

- **Классы цепей (типы дорожек):** у каждого класса — имя, ширина дорожки, зазор, размер переходного. Например: «Signal» — 0.5 мм, «Power» — 1.5 мм, «HighCurrent» — 5 мм. Классы создаются и правятся в диалоге настроек проекта.
    - Каждая цепь относится к одному классу; по умолчанию — «Signal».
    - Класс назначается только в таблице цепей (список всех цепей с выпадающим списком класса); цепь с меткой хранит класс по её имени.
    - Цепи символов питания и земли (GND, +5V …) по умолчанию попадают в класс «Power».
    - При прокладке дорожки ширина берётся из класса её цепи автоматически; вручную можно поменять для отдельного участка.
    - Нарушение зазора — ошибка. Дорожка уже, чем в классе, — **предупреждение** (бывает нужно специально сузить у вывода). Дорожка уже минимальной ширины набора правил — ошибка.

## Печать для ЛУТ и фоторезиста

Размеры и правила по умолчанию — под производство (Gerber), но плату можно изготовить и дома: для этого есть печать слоёв.

- **Печать 1:1** на лазерный принтер и в PDF, точно в масштабе (с проверочной линейкой на листе для контроля масштаба принтера).
- Выбор слоя: медь верх / медь низ. Верхний слой печатается **зеркально**, нижний — **без зеркалирования** (переключатель можно поменять вручную).
- Медь чёрная, остальное белое; опция инверсии (для фоторезиста).
- **Центровочные точки:** в каждой площадке и переходном печатается маленькое отверстие (диаметр задаётся, по умолчанию 0.5 мм), чтобы сверло при ручном сверлении не уходило.
- Метки совмещения слоёв для двухсторонней платы: печатаются за контуром на обоих слоях.
- Контур платы печатается тонкой линией.
- Можно напечатать несколько копий на одном листе.

## Документы схемы

- **Печать схемы** на принтер и в PDF; формат листа A4/A3, ориентация, масштаб «вписать в лист».
- **Рамка** вокруг поля чертежа и **упрощённый штамп** в правом нижнем углу. Не по ГОСТ, просто аккуратная табличка. Поля берутся из свойств проекта (редактируются в диалоге): название проекта, название листа, автор, организация, контакты (свободный текст: эл. почта, сайт и т. п.), ревизия, дата, «лист N из M», примечание. Автор, организация и контакты по умолчанию берутся из настроек программы и подставляются в каждый новый проект; в проекте их можно изменить. Дата по умолчанию — дата последнего сохранения, можно задать вручную. Пустые поля не печатаются.
- Рамка и штамп видны и при редактировании схемы, не только при печати.
- **Перечень элементов (BOM):** таблица «обозначения, номинал, корпус, количество», одинаковые детали сгруппированы (R1, R5, R7 — 10k — 3 шт.). Экспорт в CSV.

## Экспорт

- Gerber RS-274X — по файлу на слой.
- Сверловка — Excellon, два файла: металлизированные отверстия (PTH) и неметаллизированные (NPTH).
- Проверка результата в gerbv или во встроенном просмотрщике производителя плат.

## Сохранность работы

- **Автосохранение** с заданным интервалом (по умолчанию 5 минут): для каждого изменённого файла проекта — отдельная копия рядом с ним (исходные файлы не перезаписываются). После аварийного завершения при открытии проекта предлагается восстановление.
- **Резервные копии:** при каждом сохранении предыдущая версия файла сохраняется как `.bak`; хранится несколько последних (по умолчанию 3, задаётся в настройках).
- Список **недавних проектов** в меню «Файл».
- При закрытии с несохранёнными изменениями — запрос на сохранение.

## Автотесты

- **Архитектурное требование:** модель данных и вся логика (геометрия, нетлист, DRC/ERC, чтение/запись файлов, экспорт) — в отдельной библиотеке без зависимости от QtWidgets (только QtCore/QtGui). GUI — тонкий слой поверх неё. Тогда логику можно тестировать без окон.
- **Инструмент:** Qt Test (входит в Qt, дополнительных зависимостей нет), запуск через CTest (`ctest`) локально; скрипт сборки AppImage прогоняет тесты перед упаковкой.
- **Что проверяется:**
    - геометрия: расстояния отрезок–отрезок, отрезок–окружность, прямоугольник и т. п.; перевод мм ↔ нм и округление;
    - построение нетлиста по небольшим тестовым схемам: провода, Т-соединения, метки, символы питания, шины, несколько листов;
    - DRC и ERC: тестовые платы и схемы с заранее известными нарушениями;
    - файлы: сохранить → загрузить → сравнить (ничего не потерялось); загрузка файлов старых версий формата;
    - Gerber и Excellon: «эталонные файлы» — результат для тестовой платы один раз проверяется вручную в gerbv и кладётся в репозиторий, дальше тест сравнивает новый вывод с эталоном;
    - Undo/Redo: действие → отмена → состояние совпадает с исходным;
    - синхронизация схема → плата.
- **GUI-тестов в первой версии нет**, кроме проверки «программа запускается и открывает тестовый проект» (режим без экрана, `QT_QPA_PLATFORM=offscreen`).
- **Правило разработки:** каждая новая функция логики — вместе с тестами; при исправлении ошибки сначала пишется тест, который её воспроизводит.
- **Версия формата:** во всех JSON-файлах (`.ppcb`, `.ppsch`, `.ppbrd`, библиотека) есть поле версии формата, чтобы новые версии программы могли читать старые файлы.

## Порядок разработки (предварительно)

0. Каркас: репозиторий git, CMake, разделение на библиотеку логики и GUI, пустое окно с холстом (сетка, зум, панорамирование), первые тесты, переводы (`tr()` с первого дня).

2. Библиотека: формат JSON и первые детали.
3. Редактор схемы: расстановка УГО, провода, метки, построение цепей; ERC.
4. Редактор платы: контур, посадочные места, синхронизация со схемой, ratsnest, дорожки, переходные; DRC.
5. Экспорт Gerber + Excellon.
6. Печать для ЛУТ (1:1, зеркалирование, центровочные точки).
7. Документы схемы: печать/PDF с рамкой и штампом, BOM.
8. Скрипт сборки AppImage, первый выпуск.
